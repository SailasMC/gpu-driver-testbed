# GPU 驱动测试台 · 使用说明（v2.0）

> 一个**免 root、不依赖 Shizuku** 的真机 GPU 驱动测试软件。
> 用途：加载任意 Vulkan 驱动（自定义 ICD），跑渲染测试与跑分，并**把画面显示在屏幕上**；同时能以**系统原生驱动**作对照组。

## 安装
把 `GPUTest-*.apk` 拷到手机任意目录，用文件管理器点开安装（允许"未知来源"）。
桌面图标：深色底 + 红色三角形，名字 **「GPU 驱动测试台」**。

## 六个页签怎么用

### ① 概览
设备 / GPU / 当前选中驱动的概要。第一次进来先看这里确认"选中了哪个驱动"。

### ② 驱动
- **扫描**：自动列出
  - 已安装的驱动插件包（读启动器的 `fclPlugin` / `driver` 元数据 ⇒ 与 Zalith Launcher 2 / FCL 同一套约定）
  - 本地 `.so`：`Android/data/com.dsh.gputest/files/drivers/`、`/sdcard/Download/`、项目目录
- **从 APK 提取**：选一个驱动插件 APK ⇒ 自动取出 `lib/**` 里最大的 `.so` 并选中
- **安装插件 APK**：会话式安装（不用 root）
- **系统驱动对照**：把当前选择切换到"系统驱动"，用于"怪驱动还是怪设备"的判断

> **零权限小技巧**：把 `.so` 直接放进 `Android/data/com.dsh.gputest/files/drivers/` ⇒ 不需要任何存储权限就能被扫到。

### ③ 测试
- **驱动自测（ICD 冒烟）**：`dlopen` → 协商接口版本 → 建实例 → 枚举设备 → 建设备/队列。**这是最短的验证路径**：驱动到底能不能用，看这一步。
- **三角形绘制 + 像素校验**：建渲染目标 + 图形管线，画一个三角形，回读像素判定：
  - 期望：**有红 + 有黑 + 无其它** ⇒ "绘制正确"
  - **"整屏全红"会被专门判为异常**（clear 未生效 / 覆盖全屏，是渲染 bug 的典型形态）
- **能力清单**：设备属性、关键限制、实例/设备扩展、内存堆与内存类型 —— 直接暴露"这个驱动支持什么"

### ④ 画面（v2.0 新增）
**把渲染结果实时显示出来**：一个持续旋转的红色三角形 + **FPS 计数**。
- 渲染在原生侧完成，再用零拷贝方式写进 Android `Bitmap` 显示；
- 能看到画面 ⇒ 说明"从驱动到屏幕"这条链是通的；**看不到 / 花屏 / 崩** ⇒ 都有诊断价值。

### ⑤ 跑分
| 模式 | 量什么 |
|---|---|
| fill | 填充率（Mpixel/s） |
| blit | 图像间拷贝带宽（GB/s） |
| draw | 三角形吞吐（个/s） |
| 一键全流程 | 冒烟 → 三角形 → 三种跑分 → **综合分**（口径在界面里写明，不藏公式） |

> 失败时**不输出吞吐数字** —— 因为"能跑出数字"和"结果可信"是两回事。

### ⑥ 日志
- 实时日志（结果用颜色区分：绿=通过 / 红=失败 / 黄=警告）
- **读取启动器日志**：直接读 **`/sdcard/FCL/log/latest_game.log`** 与 `fcl.log`（ZL2 的日志在其私有目录，需先点"授权所有文件访问"）
- **导出 / 分享**：一键把整段日志发出去

## 典型用法：判断"到底是驱动的问题还是设备的问题"

```
1) 选一个自定义驱动 → ③ 驱动自测        ⇒ 能过吗？
2) 同一驱动           → ④ 画面 + ⑤ 跑分  ⇒ 画面正常吗？分数多少？
3) 切到"系统驱动"     → 重复 1) 2)        ⇒ 系统驱动正常吗？
4) 三者对照：
   系统驱动正常 + 自定义驱动崩  ⇒ 问题在驱动侧
   两者都崩                    ⇒ 问题在设备/环境
   自定义驱动部分正常          ⇒ 缩小到具体测试项（填充/拷贝/绘制）
```

## 已知边界（诚实标注）
- 只测 **Vulkan**；OpenGL/EGL 那条链（`libEGL_mesa.so` / `libglxshim.so`）尚未纳入，而实测游戏日志显示**那一环会先倒**。
- 自签名调试包，不保证任何设备可用。
- 跑分口径是自定的横向对比口径，**不是** 3DMark/GFXBench 的分数，别直接与它们比较。
