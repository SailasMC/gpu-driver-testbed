## 一、设置页（底部第 5 项 · 9.55 起）

| 区块 | 能做什么 |
|---|---|
| **Shizuku / Stellar 提权通道** | 「申请授权」→ 在 Stellar 里点允许 → 「刷新状态」。**重装 App 后授权会掉，需重新申请** ✓ |
| **设备真实数据** | 「读取真实数据」⇒ 卡片内显示**八项真数据**原文（见第四节 ✓） |
| **实时监视** | 「▶ 开始 / ■ 停止」⇒ 每 2 秒采样，**三条 sparkline 曲线**（温度 / 频率 / 占用率）+ 帧统计 + 显存 + GPU 活跃 uid ✓（可不占用 busy 位，**可与光追/跑分同时跑** ✓） |
| **导出 HTML 报告** | 生成 `/sdcard/Download/gputest-report-<时间>.html` ✓ 含**四图**（温度/频率/占用率柱状图）+ 成绩 + 帧统计 + 光追配置快照 + 探针原文 ✓ |
| 渲染 / 维护 / 关于 | 帧率上限 · 默认画面尺寸 · 清空/导出日志 · 版本信息 |

## 二、光追（画面 → 光影 → ▶ 光追 3D）

**场景**：室内竞技场（9×9×4.2 房间）12 个木箱（含叠放）+ 3 个金属油桶 + **左右墙两面镜子（反射率可调）** + 棋盘格地砖；**点光源绕房间移动**（12 秒一圈 ✓）；材质为**程序化细节**（木纹/板缝/棱边压暗 · 拉丝金属+锈 · 砖缝 · 水泥污渍 ✓）

**光追配置（6 项，全部真生效 ✓）**：

| 选项 | 取值 | 用途 |
|---|---|---|
| **阴影采样数** | 1 / 2 / 4 / 8 / 16 | **画质 ↔ 耗时**权衡（RT 最贵的一项 ✓ 跑分对比时固定此值 ✓） |
| **反射弹射** | 关 / 1 次 / 2 次 | **关掉省约一半时间** ✓ 2 次 = 镜中镜 |
| **材质细节** | 开 / 关 | A-B 对比"细节值多少帧" ✓ |
| **光晕强度** | 0/50/100/200% | 双叶光晕（近距紧 + 宽域松 ✓） |
| **灯绕行速度** | 静止 / 慢 / 快 | **静止 = 画面不变，可逐像素比对** ✓ 动 = 实时渲染演示 |
| **镜面反射率** | 50/80/97/99% | 镜子观感 + "反射是否真在算"的判据 ✓ |

**日志判据**：`BLAS=N 三角形`（与场景一致）· `回读: 已拷入位图 · 像素 min/max/均`（**未命中色是渐变** ⇒ 光线全打空 ✗；命中几何则均值随镜头漂移 ✓）

## 三、跑分与压力（测试页 / 画面 → 压力）

- **单项**：填充率 fill · 拷贝带宽 blit · 三角形吞吐 draw（各 5 秒 ✓）
- **一键跑全部驱动** ⇒ 排名表（口径透明：`0.4×fill + 0.3×blit + 0.3×draw` 各自相对最优归一 ✓ 失败项单列表不参与排名 ✓）
- **A/B 对比**：设基准 A → 切驱动 → 开始对比 ✓
- **迷你 3D**：独立最简路径（自转立方体 + 法线/视差贴图 ✓ 用于验证驱动"能不能画对" ✓）
- **压力测试**：每帧加量（ppf 可调 ✓ 停止时保留最后一帧 ⇒ 崩前那一帧就是证据 ✓）

## 四、真数据八项（**全部无需 root** ✓）

| 指标 | 来源 |
|---|---|
| **GPU 频率** | tracefs `power/gpu_frequency`（见 [GPU频率-tracefs方案](GPU频率-tracefs方案.md)） |
| **GPU 占用率** | tracefs `power/gpu_work_period`（Σactive ÷ Σwindow ✓） |
| **逐进程 / 全局 GPU 显存** | tracefs `gpu_mem/gpu_mem_total` + `dumpsys gpu` |
| **GPU / CPU / SOC / NPU / SKIN 温度** | `dumpsys thermalservice` |
| **帧时间分位 + 卡顿率 + GPU 分位** | `dumpsys gfxinfo <包名>` |
| **内存（Java / Native / Graphics）** | `dumpsys meminfo <包名>` |
| **电池温度 / 电量** | `dumpsys battery` |
| **设备与驱动** | `getprop`（含 `ro.gfx.driver.0` = 天玑游戏驱动包名 ✓） |

**已知边界**：`/sys/class/devfreq/13000000.mali/*`、`/proc/gpufreqv2/*`、`/sys/kernel/ged/*` 在未 root 时**全部 Permission denied** ✗（连 Shizuku UserService 的 shell 域也一样 ✓）—— 所以频率只能走 tracefs ✓

## 五、驱动测试（测试 → 驱动）

- 列出各来源的 Vulkan 驱动与渲染器（系统 loader / 直载 `.so` / GLES 垫片 …）
- 选中即记忆，**头部常驻显示当前驱动** ✓

## 七、常见问题（FAQ）

| 现象 | 原因 / 处理 |
|---|---|
| 「设备控制超时…无障碍服务未运行」 | **无障碍**掉了 ⇒ 重开 DSH 的无障碍 ✓ |
| 「Shizuku shell 通道建立超时」 | **Stellar/Shizuku 服务**被系统回收 ⇒ 打开 Stellar 重启服务 ✓（重启手机后必须重开 ✓） |
| 探针里 sysfs 项全空 | **正常** ✓ 见第四节已知边界 ✓ 用 tracefs / dumpsys 那几项 ✓ |
| 光追画面是**渐变**而非几何 | 光线全打空 ✗ ⇒ 看日志 `BLAS=` 是否与场景一致 + 像素统计是否漂移 ✓ |
| 实时监视读不到频率 | 频率是**变化事件** ✓ **空载时本来就无记录** ✓ 跑起来再看 ✓ |
| 报告里某图为空 | 需先开过**实时监视**采样 ✓（无样本时报告会写明"无采样" ✓） |
