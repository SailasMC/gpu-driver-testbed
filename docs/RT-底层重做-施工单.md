# 光追底层重做 · 施工单

> 背景：9.52~9.82 是在旧骨架上打补丁（几何表在 C 与 GLSL 各写一份、法线靠解析反推、接口只有推送常量）。
> 本文是**重做底层**的方案：立正确骨架 → 逐层替换 → 不做大爆炸重写。

---

## 一、现有骨架的 6 个结构性缺陷（每条都真实造成过 bug）

| # | 缺陷 | 造成过的实际 bug |
|---|---|---|
| 1 | **几何表写两份**（`rt_make_mesh` 的 `SPH/BOX` 与 `rt_comp.comp` 的 `SC/PAL` 靠注释对齐） | 场景一改，法线/材质就对不上 ✗ 每次都要手动同步 |
| 2 | **没有顶点缓冲**（几何只存在于 BLAS 内部） | 着色器**拿不到顶点/法线** ⇒ 只能"解析猜"法线 ✗；想加新物体就得改两处代码 |
| 3 | **没有材质系统**（albedo 写死在 shader 的 `if` 分支里） | 材质无法数据化；金属/木头只能靠硬编码判断 ✗ |
| 4 | **接口只有推送常量**（128 字节上限 ✗） | 无法传场景数据；`invVP` 塞不下被迫改结构 ✓ |
| 5 | **相机写死在 C 里** | 想换视角必须重新编译 ✗（刚为此编译失败过一次 ✓） |
| 6 | **没有图像累积/降噪**（单帧直接出图） | 软阴影/反射一开就噪；锯齿无法消除 ✗ |

## 二、目标架构（正确骨架）

```
    场景源（glTF / 程序化生成）
             │
             ▼
    ┌────────────────────────────┐
    │ Scene SSBO（唯一真源 ✓）    │  vertices[] normals[] indices[] primIndex[]
    │ Material SSBO              │  albedo / roughness / metallic / emissive
    │ TLAS + BLAS                │  仅用于遍历（不再兼任"数据源"）
    └────────────────────────────┘
             │  绑定：set0 b0=TLAS b1=image b2=Scene b3=Material b4=Cam
             ▼
    计算着色器：主射线 → 命中取 primIndex → 从 SSBO 取真法线 ✓
                → 阴影射线（天玑最优写法 ✓）→ 反射射线 → AO
             │
             ▼
    累积缓冲（历史帧累加 ÷ N）→ 色调映射 → 存储图像
```

**关键点**：
- **顶点/法线/索引进 SSBO** ⇒ 着色器用 `rayQueryGetIntersectionPrimitiveIndexEXT` + `rayQueryGetIntersectionBarycentricsEXT` 取**真几何法线** ✓（不再解析猜 ✗）
- **一份数据**：C 只负责"生成/加载 + 上传"，shader 只负责"读" ⇒ 第 1 条缺陷从根上消失 ✓
- **材质数据化** ⇒ 金属/木箱/水泥只是参数不同 ✓
- **累积** ⇒ 软阴影/反射噪声随帧数收敛，顺带**抗锯齿** ✓

## 三、迁移步骤（每步都可独立验收，不破坏现有可跑版本）

| 步 | 内容 | 验收标准 | 风险 |
|---|---|---|---|
| **S1** | 加 **Scene SSBO + Material SSBO**（几何仍由现有程序化生成器产出，但**改为写进 buffer** ✓） | 画面与现在**逐像素一致**（回归 ✓）+ 日志里 SSBO 字节数正确 | 低 |
| **S2** | 着色器**改读 SSBO**，法线改成用 `primIndex + barycentrics` 从顶点算 ✓ | 球/桶/箱的明暗过渡与现在一致或更好 ✓ | 中 |
| **S3** | **材质表**数据化（albedo/roughness/metallic）⇒ 金属桶 vs 木箱 vs 水泥墙由参数决定 ✓ | 改一个参数就能换材质 ✓ 不用重编译 shader | 低 |
| **S4** | **累积缓冲**（TAA 式历史累加）⇒ 软阴影/反射噪声收敛 + 抗锯齿 ✓ | 静止时噪声逐帧下降 ✓ 帧时间不变（+1 个 image copy ✓） | 中 |
| **S5** | **场景文件**（glTF / JSON）⇒ 用工作区已有的 `iris-host/gltf2mesh.py` 与 `emit_mesh_h.py` 产出 SSBO 二进制 ✓ | 换场景不用改代码 ✓ | 中 |
| **S6** | 相机：**可切换**（环绕 / 第一人称漫游 / 固定机位）＋速度可调 ✓ | 界面上能切 ✓ | 低 |

> 顺序理由：S1/S2 是所有后续的基础（数据流正确 ✓）；S3/S4 提升观感；S5 让"换场景"零成本；S6 让它像游戏实机 ✓。

## 五、回归保护（每次都要做 ✓）

1. 构建后 `aapt2 dump badging` 确认 versionCode ✓
2. 日志判据：`BLAS=N 三角形` 与设计值一致 ✓、`像素 min/max/均` 随相机运动**平滑漂移** ✓、`已拷入位图` 无 `X` 前缀 ✓
3. 每步都用**同一场景同一机位**对比上一版的像素统计（差异应可解释 ✓）
4. 任一步失败 ⇒ 断言拦在写入前 ✓（`rep()`/`assert count==1` 的纪律 ✓），绝不产生"半新半旧"的树 ✓
